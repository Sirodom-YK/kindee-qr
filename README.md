# KinDee QR (กินดี QR)

AI-Powered Food Scanner — โครงงานนักศึกษาสำหรับสแกนบาร์โค้ด/QR Code หรือถ่ายรูป เพื่อตรวจสอบข้อมูลอาหาร ขนม เครื่องดื่ม ผัก และผลไม้ (ส่วนประกอบ สารก่อภูมิแพ้ และโภชนาการ)

> เดิมชื่อ BeautiQR (ระบบข้อมูลเครื่องสำอาง) — เปลี่ยนมาเป็นระบบข้อมูลอาหารทั้งหมดแล้ว ถ้าใช้ฐานข้อมูล Supabase เดิม ให้รัน `supabase/migrate-food.sql` ก่อน

## แหล่งข้อมูล

| แหล่ง | ใช้ทำอะไร | API Key |
|---|---|---|
| Supabase ตาราง `products` | สินค้าที่ทีมงานเพิ่มเอง และ QR Code ของโปรเจกต์ (`KINDEE-xxxx`) | anon key (เปิดเผยได้) |
| [Open Food Facts](https://world.openfoodfacts.org/) | สินค้าที่มีบาร์โค้ด (รวมสินค้าไทยจำนวนหนึ่ง): ชื่อ ส่วนประกอบ สารก่อภูมิแพ้ วัตถุเจือปน โภชนาการ Nutri-Score และ NOVA | ไม่ต้องใช้ |
| [USDA FoodData Central](https://fdc.nal.usda.gov/) | โภชนาการของผักผลไม้/วัตถุดิบสดที่ไม่มีบาร์โค้ด (ชุดข้อมูล Foundation + SR Legacy) | ฟรีที่ https://api.data.gov/signup/ (เก็บเป็น secret ฝั่งเซิร์ฟเวอร์) |

ทางเลือกในอนาคต: ผักพื้นบ้านไทยที่ USDA ไม่มี สามารถนำเข้าจากตารางคุณค่าทางโภชนาการอาหารไทย (INMUCAL / Thai Food Composition Database ของสถาบันโภชนาการ ม.มหิดล) เป็น CSV ลงตาราง `products` ได้

## สถานะปัจจุบัน: ขั้นที่ 6 (ครบทุกขั้นแล้ว) — อ่านภาพฉลากด้วย AI + ระบบจัดการข้อมูล Admin

เว็บไซต์ HTML/CSS/JavaScript ธรรมดา (ไม่มี build tool, ไม่ต้อง `npm install`) ครบทุกฟังก์ชันตามที่ออกแบบไว้แล้ว:

- หน้าแรก (`index.html`) — แสดงสินค้าทั้งหมดจากตาราง `products` ใน Supabase
- หน้าสแกน (`scan.html`) — เปิดกล้อง สแกน QR Code/บาร์โค้ด แล้วค้นหาในระบบและ Open Food Facts ให้อัตโนมัติ และมีทางเลือก **ถ่ายรูป** ทั้งฉลากสินค้า (AI อ่านข้อความ) และผักผลไม้สด (AI ระบุชนิด แล้วดึงโภชนาการจาก USDA)
- หน้ารายละเอียดสินค้า (`product-detail.html`) — รับได้ทั้ง `?id=<uuid>` (จาก Supabase), `?barcode=<code>` (จาก Supabase ก่อน แล้ว Open Food Facts) และ `?food=<ชื่ออังกฤษ>&name_th=<ชื่อไทย>` (ผักผลไม้สดจาก USDA) แสดงตารางโภชนาการต่อ 100 กรัม สารก่อภูมิแพ้ Nutri-Score และ NOVA (ถ้ามี)
- หน้าค้นหาสินค้า (`search.html`) — ค้นหาด้วยชื่อสินค้าหรือแบรนด์ในฐานข้อมูลของเรา ถ้าไม่พบจะค้นต่อใน Open Food Facts
- หน้า AI Assistant (`ai-assistant.html`) — ให้ Gemini ช่วยอธิบายส่วนประกอบ สรุปข้อมูลโภชนาการ หรือแปลภาษา จากข้อมูลจริงของสินค้าที่เลือก
- หน้า Admin (`admin.html`) — ต้อง login ก่อนใช้งาน เพิ่ม/แก้ไข/ลบสินค้าในตาราง `products` ผ่านเว็บได้โดยตรง และตรวจ/อนุมัติข้อมูลที่ผู้ใช้ส่งเข้ามา
- หน้าส่งข้อมูลสินค้า (`submit.html`) — เมื่อสแกน/ค้นหาแล้วไม่พบหรือข้อมูลไม่ครบ ผู้ใช้พิมพ์ข้อมูลตามฉลากส่งให้ทีมงานได้ (ไม่ต้อง login)

### หลักการทำงานของหน้าสแกน QR (`scan.html` / `js/scan.js`)

1. เปิดกล้องด้วยไลบรารี html5-qrcode (เบราวเซอร์จะขออนุญาตใช้กล้องก่อน)
2. เมื่อสแกนเจอ QR Code จะนำค่าที่อ่านได้ไปค้นหาในตาราง `products` โดยลองจับคู่กับ `qr_code_value` ก่อน แล้วลอง `barcode`
3. ถ้าพบสินค้าในระบบของเรา → เปิดหน้า `product-detail.html?id=...` ให้อัตโนมัติ
4. ถ้าไม่พบ และค่าที่สแกนได้มีรูปแบบเหมือนบาร์โค้ด (ตัวเลข 8-14 หลัก) → ลองค้นจาก Open Food Facts API ต่อ ถ้าพบ → เปิดหน้า `product-detail.html?barcode=...`
5. ถ้าไม่พบทั้งสองแหล่ง และค่าที่สแกนได้เป็น URL ที่ขึ้นต้นด้วย `http://` หรือ `https://` เท่านั้น → แสดงลิงก์ให้ผู้ใช้เห็นชัด ๆ พร้อมคำเตือน และให้ผู้ใช้กดเปิดเองในแท็บใหม่ (ระบบจะไม่เปิดลิงก์จากภายนอกให้อัตโนมัติ และจะไม่เปิด scheme อื่นที่อาจเป็นอันตราย เช่น `javascript:`)
6. ถ้าไม่พบข้อมูลเลย → แจ้งตามจริงว่าไม่พบข้อมูล พร้อมปุ่มไปค้นหาด้วยชื่อสินค้า, สแกนใหม่, หรือถ่ายรูปฉลากสินค้าแทน

### อ่านภาพฉลากด้วย AI แทนการจับคู่ภาพ (`js/label-ocr.js`)

**หลักการสำคัญ:** ฟีเจอร์นี้ **ไม่ใช่** การค้นหาสินค้าด้วยความคล้ายของภาพ (แบบ "ถ่ายรูปแล้วเจอของคล้ายกัน" ของช้อปปี้) เพราะการจับคู่จากรูปลักษณ์เสี่ยงต่อการระบุสินค้าผิดตัว (สินค้าคนละสูตร/ของปลอมมักมีหน้าตาคล้ายกัน) ซึ่งอาจทำให้ผู้ใช้เข้าใจผิดเรื่องส่วนประกอบหรือคำเตือนได้ ขัดกับกฎ "ห้ามสร้างข้อมูลจากการคาดเดา" ของระบบนี้

สิ่งที่ทำจริงคือ:
1. ผู้ใช้ถ่าย/เลือกรูปฉลากสินค้าที่หน้า `scan.html`
2. ภาพถูกย่อขนาดด้วย canvas ฝั่งเบราวเซอร์ก่อนส่ง (ให้ตัวอักษรยังอ่านออกแต่ไฟล์ไม่ใหญ่เกินไป)
3. ส่งไปให้ Gemini ผ่าน Edge Function ด้วย action `read_label_image` — Gemini **อ่านเฉพาะตัวอักษรที่เห็นจริงในภาพ** (ชื่อสินค้า, แบรนด์, บาร์โค้ด) เท่านั้น ไม่เดา ฟิลด์ที่อ่านไม่ชัดจะได้ `null`
4. เว็บไซต์นำข้อความที่อ่านได้ไปค้นหาต่อแบบเดียวกับการสแกน QR/บาร์โค้ด: ถ้ามีบาร์โค้ด ค้นใน Supabase แล้ว Open Food Facts ก่อน ถ้าไม่พบจึงค้นด้วยชื่อ/แบรนด์ (`searchProductsByText` แล้ว `searchOpenFoodFacts`)
5. ถ้าค้นด้วยชื่อ/แบรนด์พบหลายรายการ จะโชว์เป็นรายการให้ **ผู้ใช้เลือกเอง** พร้อมข้อความเตือนชัดเจนว่า "เป็นผลการค้นหา ไม่ใช่การยืนยัน" — ไม่เลือกหรือยืนยันให้อัตโนมัติ

### ผักผลไม้สด: ถ่ายรูปแล้วให้ AI ระบุชนิด

ผักผลไม้สดไม่มีฉลากให้อ่าน จึงเป็นกรณีเดียวที่ใช้ AI ดูจากรูปลักษณ์ — และเพราะเป็นการ "คาด" ไม่ใช่การอ่าน ระบบจึงออกแบบให้ปลอดภัยไว้ก่อน:
1. ภาพเดียวกันส่งไปที่ action `read_label_image` (เรียก Gemini ครั้งเดียว) ซึ่งตอบกลับด้วย `is_packaged` ถ้าเป็น `false` จะได้ `produce_name_th`, `produce_name_en` และ `confidence` มาด้วย
2. หน้าเว็บแสดง "AI คาดว่าเป็น ..." พร้อมระดับความมั่นใจ และให้ **ผู้ใช้กดยืนยันเอง** ก่อน
3. เมื่อยืนยันแล้วจึงเปิด `product-detail.html?food=...` ซึ่งเรียก action `usda_search` ของ Edge Function ไปค้น USDA FoodData Central และแสดงค่าโภชนาการต่อ 100 กรัม พร้อมคำเตือนว่าเป็นค่าเฉลี่ยของวัตถุดิบดิบ

### ข้อมูลจาก Open Food Facts (`js/openfoodfacts.js`)

Open Food Facts เป็นฐานข้อมูลสาธารณะที่ไม่มีฟิลด์ "วิธีเก็บรักษา" หรือ "คำเตือน" โดยตรง ระบบจึงแสดงเฉพาะฟิลด์ที่ API ส่งมาจริง (ชื่อ, แบรนด์, รูปภาพ, ประเภทสินค้า, ส่วนประกอบ, สารก่อภูมิแพ้, วัตถุเจือปนอาหาร, โภชนาการ, Nutri-Score, NOVA) และระบุชัดเจนในหน้ารายละเอียดว่า "ไม่มีข้อมูล" สำหรับฟิลด์ที่ไม่มี — **ห้ามแต่งข้อมูลขึ้นมาเองเด็ดขาด** หน้ารายละเอียดจะแสดงป้ายกำกับแหล่งที่มา (ข้อมูลในระบบ KinDee QR, Open Food Facts หรือ USDA FoodData Central) และข้อความเตือนว่าข้อมูลจากฐานข้อมูลสาธารณะยังไม่ผ่านการตรวจสอบโดยทีมงาน พร้อมสถานะความครบถ้วนของข้อมูลเสมอ

รูปแบบข้อมูลโภชนาการ (`nutrition` jsonb) ใช้ร่วมกันทุกแหล่ง (ดู `js/nutrition.js`): `energy_kcal`, `protein_g`, `fat_g`, `carbohydrates_g`, `sugars_g`, `fiber_g`, `sodium_mg` ทั้งหมดต่อ 100 กรัม

### AI Assistant ด้วย Gemini API (`ai-assistant.html` / `js/ai-assistant.js` / `js/gemini.js`)

**สถาปัตยกรรมสำคัญ:** Gemini API Key เป็นความลับที่ **ห้ามฝังในโค้ดฝั่งผู้ใช้โดยเด็ดขาด** (ต่างจาก Supabase anon key ที่ออกแบบมาให้เปิดเผยได้) เว็บไซต์นี้เป็น static site ล้วนไม่มี backend ของตัวเอง จึงใช้ **Supabase Edge Function** (`supabase/functions/gemini-proxy/index.ts`) เป็นตัวกลาง: หน้าเว็บเรียก Edge Function ผ่าน `supabaseClient.functions.invoke(...)` → Edge Function (รันบนเซิร์ฟเวอร์ของ Supabase) ค่อยแนบ Gemini API Key (เก็บเป็น secret ฝั่งเซิร์ฟเวอร์) แล้วเรียก Gemini จริงอีกที คีย์จึงไม่ปรากฏในโค้ดฝั่งผู้ใช้เลย

หลักการใช้ AI ในระบบนี้:
- ใช้ได้เฉพาะ **แปล** และ **อธิบาย** ข้อมูลที่มีอยู่จริงในระบบเท่านั้น (พรอมป์ใน Edge Function กำกับไว้ชัดเจน)
- ถ้าข้อมูลต้นฉบับไม่มี (เช่น สินค้าจาก Open Food Facts ที่ไม่มีข้อมูลโภชนาการ) ปุ่มที่เกี่ยวข้องจะถูกปิดใช้งานไปเลย ไม่ส่งไปให้ AI เดา
- หน้า AI Assistant แสดง "ข้อมูลต้นฉบับจากระบบ" และ "คำอธิบายจาก AI (Gemini)" แยกกันชัดเจนเสมอ พร้อมข้อความเตือนว่า AI ไม่ได้ยืนยันความถูกต้อง ความแท้ หรือความปลอดภัยของสินค้า

### ระบบ Admin (`admin.html` / `js/admin.js`)

หน้า Admin ใช้ **Supabase Auth** (เข้าสู่ระบบด้วยอีเมล/รหัสผ่าน) แยกสิทธิ์คนละชุดกับผู้ใช้ทั่วไปอย่างชัดเจน:
- ผู้ใช้ทั่วไป (ไม่ login): อ่านข้อมูลสินค้าได้อย่างเดียว (เหมือนเดิมทุกขั้นตอนที่ผ่านมา)
- ผู้ดูแลระบบ (login แล้ว): เพิ่ม/แก้ไข/ลบสินค้าได้ผ่านฟอร์มในหน้าเว็บ

ความปลอดภัยบังคับจริงที่ชั้นฐานข้อมูลด้วย Row Level Security (ดูหัวข้อตั้งค่าด้านล่าง) ไม่ได้พึ่งแค่การซ่อนปุ่มในหน้าเว็บ — ทดสอบแล้วว่าคำขอที่ไม่ได้ login (ใช้ anon key เปล่า ๆ) ถูก Supabase ปฏิเสธการเขียนข้อมูลจริง (`new row violates row-level security policy`)

### ข้อมูลจากผู้ใช้ + การอนุมัติ (`submit.html` / `js/submit.js` / ตาราง `product_submissions`)

1. ทุกจุดที่ "ไม่พบข้อมูล" (หน้าสแกน, ถ่ายรูป, หน้ารายละเอียด, หน้าค้นหา) และกล่อง "ข้อมูลยังไม่ครบ" มีปุ่ม **ส่งข้อมูลสินค้านี้ให้เรา** ซึ่งเปิด `submit.html` พร้อมเติมบาร์โค้ด/ชื่อไว้ให้
2. ข้อมูลที่ส่งจะถูกบันทึกในตาราง `product_submissions` สถานะ `pending` เท่านั้น — **ไม่แสดงบนเว็บ** เพราะหน้าเว็บอ่านจากตาราง `products` อย่างเดียว
3. RLS บังคับว่าผู้ใช้ทั่วไป "ส่งได้อย่างเดียว" อ่านข้อมูลที่คนอื่นส่งไม่ได้ และส่งข้อมูลที่อนุมัติตัวเองไม่ได้ มีการจำกัดความยาวทุกช่อง และมีช่องกับดักบอท (honeypot)
4. ผู้ดูแลเห็นรายการรอตรวจในหน้า Admin กด **ตรวจสอบและอนุมัติ** → ฟอร์มสินค้าเปิดพร้อมข้อมูลที่ผู้ใช้ส่งมา (ถ้าบาร์โค้ดมีในระบบแล้ว จะเติมเฉพาะช่องที่ยังว่าง ไม่ทับข้อมูลเดิม) ตรวจ/แก้ให้ตรงฉลากแล้วกดบันทึก → สินค้าขึ้นเว็บ และข้อมูลจากผู้ใช้เปลี่ยนเป็น `approved` หรือกด **ปฏิเสธ** → `rejected`

5. **รูปสินค้า:** ถ้าสินค้ามีรูปอยู่แล้ว (ในระบบหรือ Open Food Facts) ฟอร์มจะใช้รูปเดิมให้ ผู้ใช้กด "เปลี่ยนรูป" เพื่ออัปโหลดรูปใหม่ได้ (ย่อเป็น JPEG 1024px ฝั่งเบราว์เซอร์ก่อนอัปโหลดเข้า Storage bucket `submission-images`) ถ้าผู้ดูแลปฏิเสธ รูปที่อัปโหลดจะถูกลบ
6. **เสนอแก้ไขสินค้าที่พบแล้ว:** หน้ารายละเอียดมีปุ่ม **✏️ แก้ไขข้อมูล** ที่มุมขวาบน เปิด `submit.html` พร้อมข้อมูลปัจจุบัน ผู้ใช้แก้แล้วส่ง (`kind = edit`) หน้า Admin จะไฮไลต์ช่องที่เปลี่ยนพร้อมค่าเดิมให้เทียบ — ยังต้องอนุมัติก่อนแสดงเหมือนเดิม

ข้อจำกัด: ยังไม่มี rate limit ต่อผู้ใช้ (เว็บ static ไม่มี backend ของตัวเอง) ถ้าโดนสแปมให้ลบในตารางได้ หรือเพิ่ม CAPTCHA (เช่น Cloudflare Turnstile) ในอนาคต

## ระบบของในบ้าน — ติดตามวันหมดอายุ ใช้ร่วมกันทั้งบ้าน

ผู้ใช้สมัครด้วยอีเมล + รหัสผ่าน (`login.html`) แล้วสร้าง "บ้าน" เชิญคนในบ้าน/รูมเมทด้วยลิงก์เชิญ (ใช้ได้ 7 วัน) ทุกคนในบ้านเห็นและแก้รายการของชุดเดียวกัน

| หน้า | ทำอะไร |
|---|---|
| `pantry.html` | รายการของแยกสี 🔴 หมดอายุแล้ว / 🟠 ใกล้หมด (≤ 3 วัน) / 🟢 ยังอีกนาน / ⚪ ไม่มีวันหมดอายุ, เพิ่มของด้วยการสแกน/พิมพ์บาร์โค้ด/กรอกเอง, ถ่ายรูปวันที่ให้ AI อ่าน, ปุ่ม −1 / ใช้หมด / ทิ้ง |
| `household.html` | สร้าง/เข้าร่วมบ้าน, สมาชิก, ลิงก์เชิญ, ออกจากบ้าน, ตั้งค่าแจ้งเตือน |
| `pantry-report.html` | ใช้ทัน vs หมดอายุ/ทิ้ง รายเดือน + กราฟ 6 เดือน + ประเภทที่ทิ้งบ่อย |

- **OCR วันหมดอายุ:** action `read_expiry_date` ให้ Gemini คัดลอกตัวเลขตามที่เห็น แล้ว `js/expiry-date.js` แปลงปี (พ.ศ. 4 หลัก / ปี 2 หลักเลือกแบบที่อยู่ในช่วง 1 ปีก่อน–10 ปีข้างหน้า / มีแค่เดือน-ปีใช้วันสุดท้ายของเดือน) ตัดวันผลิตทิ้ง และให้ผู้ใช้กดยืนยันทุกครั้ง
- **Web Push:** เว็บเป็น PWA (`manifest.json` + `sw.js`) ผู้ใช้กดเปิดแจ้งเตือนในหน้าบ้านของฉัน ทุกเช้า 08:00 `pg_cron` เรียก edge function `expiry-notifier` ซึ่งรวมของที่ใกล้หมดของทุกบ้านที่ผู้ใช้อยู่เป็นแจ้งเตือนเดียว (ค่าเริ่มต้น 3 วันก่อน + วันที่หมด ปรับได้) บน iPhone ต้อง "เพิ่มลงหน้าจอโฮม" ก่อน (iOS 16.4+) และเว็บต้องเปิดผ่าน HTTPS
- **ความปลอดภัย:** RLS ทุกตาราง สมาชิกเห็นเฉพาะของบ้านตัวเอง การเข้าร่วม/ออกจากบ้านทำผ่าน RPC เท่านั้น สมาชิกเห็นแค่ชื่อที่ตั้งเอง ไม่เห็นอีเมลกัน และบทบาทผู้ดูแลแยกไว้ในตาราง `app_admins` (ผู้ใช้ทั่วไป login แล้วก็แก้ข้อมูลสินค้าไม่ได้)

### วิธีตั้งค่า (ทำครั้งเดียว ตามลำดับ)
1. SQL Editor: รัน `supabase/admin-role.sql` — **แก้อีเมลบรรทัดสุดท้ายเป็นอีเมลผู้ดูแลก่อน** ไม่งั้นจะเข้าหน้า Admin ไม่ได้
2. SQL Editor: รัน `supabase/pantry.sql`
3. Dashboard > Authentication > Sign In / Providers: เปิด Email และ "Allow new users to sign up" / URL Configuration: ตั้ง Site URL เป็นที่อยู่เว็บจริง และเพิ่ม `<ที่อยู่เว็บ>/login.html` ใน Redirect URLs
4. สร้าง VAPID key: `npx web-push generate-vapid-keys` → ใส่ **Public Key** ใน `js/push-config.js`
5. ตั้ง secrets แล้ว deploy:
   ```
   npx supabase secrets set VAPID_PUBLIC_KEY=<public> VAPID_PRIVATE_KEY=<private> VAPID_SUBJECT=mailto:<อีเมลคุณ> CRON_SECRET=<สุ่มข้อความยาว ๆ>
   npx supabase functions deploy gemini-proxy
   npx supabase functions deploy expiry-notifier --no-verify-jwt
   ```
6. คัดลอก `supabase/cron.example.sql` เป็น `supabase/cron.sql` (ไฟล์นี้ถูก .gitignore ไว้ ไม่ขึ้น GitHub) แก้ `YOUR_CRON_SECRET` ให้ตรงกับข้อ 5 แล้วรันใน SQL Editor

## วิธีตั้งค่า Admin (ทำครั้งเดียว)

1. สร้างผู้ใช้สำหรับผู้ดูแลระบบ: ไปที่ Supabase Dashboard > **Authentication > Users** > **Add user** ใส่อีเมลและรหัสผ่านที่ต้องการ (เลือก "Auto Confirm User" เพื่อไม่ต้องยืนยันอีเมล)
2. เปิดไฟล์ `supabase/admin-policies.sql` วาง SQL ทั้งหมดใน Supabase Dashboard > **SQL Editor** แล้วกด Run (เพิ่มสิทธิ์ insert/update/delete ให้เฉพาะผู้ใช้ที่ login แล้วเท่านั้น)
3. เปิดไฟล์ `supabase/submissions.sql` วางใน SQL Editor แล้วกด Run (สร้างตารางข้อมูลจากผู้ใช้ + สิทธิ์ "ส่งได้อย่างเดียว") จากนั้นรัน `supabase/submission-edits.sql` (รูปสินค้า + การเสนอแก้ไข)
4. เปิด `admin.html` ล็อกอินด้วยอีเมล/รหัสผ่านที่สร้างไว้ในขั้นตอนที่ 1

## วิธีตั้งค่า Gemini API + Supabase Edge Function (ทำครั้งเดียว)

1. ขอ Gemini API Key (ฟรี) ที่ https://aistudio.google.com/ → เมนู **Get API Key**
2. ติดตั้งและใช้ Supabase CLI ผ่าน `npx` (ไม่ต้องติดตั้งแยก) เปิด PowerShell ที่ `C:\beautiQR` แล้วรันตามลำดับ:

   ```powershell
   cd C:\beautiQR

   # ล็อกอินเข้า Supabase (จะเปิดเบราวเซอร์ให้ยืนยัน)
   npx supabase login

   # เชื่อมโปรเจกต์นี้กับ Supabase project ของคุณ
   # (project-ref คือส่วนหน้าของ URL โปรเจกต์ — ของคุณคือ wgcxrawztwaqnunvytkn ใส่ไว้ให้แล้ว)
   npx supabase link --project-ref wgcxrawztwaqnunvytkn

   # ตั้งค่า Gemini API Key เป็น secret ฝั่งเซิร์ฟเวอร์ (ไม่ใช่ไฟล์ในโค้ด)
   npx supabase secrets set GEMINI_API_KEY=<YOUR_GEMINI_API_KEY>

   # (แนะนำ) ตั้งค่า USDA API Key สำหรับข้อมูลโภชนาการผักผลไม้สด ขอฟรีที่ https://api.data.gov/signup/
   # ถ้าไม่ตั้ง ระบบจะใช้ DEMO_KEY ซึ่งจำกัดแค่ 30 ครั้ง/ชั่วโมง
   npx supabase secrets set USDA_API_KEY=<YOUR_USDA_API_KEY>

   # deploy ฟังก์ชัน gemini-proxy ขึ้น Supabase
   npx supabase functions deploy gemini-proxy
   ```

3. เสร็จแล้ว — เว็บไซต์จะเรียก Gemini ผ่าน Edge Function นี้โดยอัตโนมัติ (ไม่ต้องแก้โค้ดฝั่งผู้ใช้เพิ่ม)

> หากรุ่นโมเดลที่ตั้งไว้ใน `GEMINI_MODEL` (ปัจจุบันคือ `gemini-3.8-flash`) ใช้กับคีย์ของคุณไม่ได้หรือถูกปลดออกไปแล้ว ให้เปิดไฟล์ `supabase/functions/gemini-proxy/index.ts` แล้วแก้ค่า `GEMINI_MODEL` เป็นชื่อรุ่นที่ใช้ได้จริงใน Google AI Studio ของคุณ จากนั้นรัน `npx supabase functions deploy gemini-proxy` ใหม่อีกครั้ง

> **ข้อควรรู้เรื่องโควต้าฟรี:** บัญชี Gemini API แบบฟรีมีโควต้าจำกัดมาก (ตัวอย่างที่เจอจริงคือ 20 requests/วัน/โมเดล) หากเรียกใช้ AI Assistant หรืออ่านภาพฉลากแล้วได้ข้อความ error "เรียกใช้ AI ไม่สำเร็จ" ให้ลองดูที่ Google AI Studio ว่าโควต้าหมดหรือยัง (จะฟ้องกลับมาเป็น error 429 RESOURCE_EXHAUSTED ใน log ของ Edge Function) ถ้าต้องใช้บ่อยสำหรับนำเสนอ/สอน ควรเปิด billing (pay-as-you-go) ไว้ก่อน

## วิธีตั้งค่า Supabase (ทำครั้งเดียว)

1. สร้างบัญชีและโปรเจกต์ใหม่ (ฟรี) ที่ https://supabase.com/ — ตอนสร้างโปรเจกต์ ระบบจะให้ตั้งรหัสผ่านฐานข้อมูล (Database Password) เก็บไว้ให้ดี (ไม่ใช่รหัสที่ใช้ในโค้ด)
2. เมื่อโปรเจกต์พร้อมใช้งาน ไปที่เมนู **SQL Editor** ทางซ้าย แล้ววาง SQL จากไฟล์ `supabase/schema.sql` ของโปรเจกต์นี้ แล้วกด Run (จะสร้างตาราง `products` พร้อมเปิด Row Level Security และอนุญาตให้อ่านข้อมูลได้แบบสาธารณะ)
3. (แนะนำ) วาง SQL จากไฟล์ `supabase/seed.sql` แล้วกด Run เพื่อเพิ่มสินค้าอาหารตัวอย่าง 5 รายการสำหรับทดสอบ (QR `KINDEE-0001` ถึง `KINDEE-0005`)
   - ถ้าเป็นโปรเจกต์ Supabase เดิมของ BeautiQR ให้รัน `supabase/migrate-food.sql` ก่อน (เพิ่มคอลัมน์อาหาร + ลบข้อมูลเครื่องสำอางเดิม) แล้วค่อยรัน `seed.sql`
4. ไปที่ **Project Settings > API** แล้วคัดลอกค่า 2 ค่า:
   - **Project URL**
   - **anon public key** (ไม่ใช่ `service_role` key — ห้ามใช้ `service_role` key ในโค้ดฝั่งผู้ใช้โดยเด็ดขาด เพราะคีย์นั้นข้ามการตรวจสอบสิทธิ์ทั้งหมด)
5. เปิดไฟล์ `js/supabase-config.js` ในโปรเจกต์นี้ แล้วแทนค่า `YOUR_SUPABASE_PROJECT_URL` และ `YOUR_SUPABASE_ANON_KEY` ด้วยค่าจริงที่คัดลอกมา บันทึกไฟล์

> **หมายเหตุด้านความปลอดภัย:** `anon public key` ออกแบบมาให้ฝังในโค้ดฝั่งผู้ใช้ได้ (ไม่ใช่ความลับ) ความปลอดภัยของข้อมูลมาจาก Row Level Security (RLS) policy ที่กำหนดไว้ใน `supabase/schema.sql` (อ่านได้สาธารณะ) และ `supabase/admin-policies.sql` (เขียนได้เฉพาะผู้ใช้ที่ login แล้ว)

## สรุปสถานะ

ครบทุกขั้นตอนที่วางแผนไว้ตั้งแต่แรกแล้ว (ขั้นที่ 1–6) ส่วนที่ทำได้ดีขึ้นต่อจากนี้ (ไม่บังคับ) เช่น: เพิ่ม rate limiting ที่ Edge Function เพื่อป้องกันผู้ไม่หวังดีเรียกใช้ Gemini จนโควต้าหมด, เพิ่ม pagination ให้หน้าค้นหา/admin เมื่อสินค้ามีจำนวนมาก, หรือเชื่อมลิงก์ไปยังระบบตรวจสอบเลขสารบบอาหาร (เลข อย. 13 หลัก) ของ อย. ไทยในหน้ารายละเอียดสินค้า
